# Retraining-Free Test-Time Scale Adaptation for Edge Sperm Tracking

This repository accompanies the manuscript:

> **Retraining-Free Test-Time Scale Adaptation for Quantized Sperm Detection and Tracking on Edge Devices**

This review repository contains the model definition, training and deployment code, evaluation scripts, aggregated results, figure-generation assets, and the ONNX/RKNN model artifacts used in the study. Raw VISEM-Tracking videos and annotations are not redistributed; they should be obtained from the official dataset release.

## What the method contains

1. A retraining-free test-time scale adaptation rule that estimates one output-box scale per unlabeled video from image cues and the upper tail of the detector's score distribution.
2. A compact, NPU-native global-context gate (`GatedCtx`) placed at the P3/8 output. The repository includes both the full YOLOv8n-GatedCtx model definition and the P3-only export definition.
3. Export-time removal of detection branches that produce no valid detections in FP32 or INT8.
4. Cross-frame sampling with association thresholds adjusted as the detection interval changes.

## Repository layout

- `src/model/`: `GatedCtx` implementation and YOLOv8n model YAML files.
- `src/board/`: RKNN conversion, inference, scale adaptation, tracking and scoring scripts.
- `src/training/`: training and detection-dump scripts used for the official and third-party comparisons.
- `paper_visem/v2/`: scripts that generate the paper figures.
- `paper_visem/scripts/`: tracker and detector comparison experiments.
- `paper_visem/data/`: aggregated result JSON files, deployment measurements, training logs and model configurations.
- `models/`: final ONNX and RKNN artifacts, with SHA-256 checksums.
- `paper_visem/figures/`: the 13 figures used in the manuscript and their generation assets.

## Environment

The analysis code was run with Python 3.11 and the versions in `requirements.txt`. A CUDA-capable PyTorch installation is optional for analysis but required for practical retraining and GPU inference.

Rockchip conversion additionally requires the Linux x86 `rknn-toolkit2` environment from Rockchip. Board execution requires `rknn-toolkit-lite2` and the RK3568 runtime; these packages are not portable pip dependencies and are therefore not vendored here.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Add the source directories to `PYTHONPATH` when running scripts directly:

```bash
export PYTHONPATH="$PWD/src/model:$PWD/src/board:$PWD/src/training:$PWD/paper_visem/scripts:$PWD/paper_visem/v2"
```

On PowerShell:

```powershell
$env:PYTHONPATH="$PWD\src\model;$PWD\src\board;$PWD\src\training;$PWD\paper_visem\scripts;$PWD\paper_visem\v2"
```

## Dataset

The experiments use the public VISEM-Tracking dataset:

- Project: <https://github.com/simulamet-host/visem-tracking>
- Checkpoints and dataset materials: <https://huggingface.co/datasets/SimulaMet-HOST/VISEM-Tracking>

The paper uses the official 16-video training split and the four held-out videos `52`, `54`, `60` and `82`, with only the normal-sperm class (`class 0`). Dataset files must be downloaded under their original license. Detection dumps and annotations are not included in this repository.

Expected local layout for scripts that need the dataset:

```text
datasets/
  visem_official/
    data.yaml
    train/images/
    val/images/
  visem_tracking/
    mot_gt/
    mot_gt_train/
```

The four held-out videos are never used to fit `kappa` or any model parameter. The scale-adaptation rule uses only the current video's image cues and detector-score distribution at inference time.

## Reproduce figures

Most figure scripts read the aggregated files in `paper_visem/data/`:

```bash
cd paper_visem
python v2/make_v2_fig_train.py
python v2/make_v2_fig_dataset.py
python v2/make_v2_fig_deploy.py
python v2/make_v2_fig_tracker.py
```

`make_v2_fig_deploy.py` produces both the board-latency figure and the MOTA-throughput figure. Figures that require the full frame-level detection dumps are generated by `paper_visem/v2/make_v2_fig_tracking.py` after the detection repositories have been downloaded or regenerated with `src/training/infer_dump.py`.

## Run the edge pipeline

The board-side entry points are:

- `src/board/rknn_headraw_pipeline.py`: RKNN decoding, tracking and output-scale correction.
- `src/board/rknn_lite_bench_full.py`: NPU and end-to-end timing.
- `src/board/validate_labelfree_scale.py`: reconstruct the label-free scale rule.
- `src/board/validate_scale_calibration.py`: evaluate fixed and adaptive adaptation settings.
- `src/board/export_head_raw_onnx.py` and `src/board/rknn_convert.py`: model export and conversion.

Several scripts retain the absolute paths of the original Linux experiment environment. Adjust those paths or pass the corresponding command-line arguments when reproducing on another machine.

Training and detection-dump entry points are documented in `src/training/README.md`. They are provided to expose the complete experimental pipeline; exact retraining requires the public dataset, an appropriate GPU environment, and the training output paths described there.

## Model artifacts

`models/` includes:

- `stock_v8n_gctx_pruned_448_int8.rknn`: final pruned INT8 board model.
- `stock_v8n_gctx_448_int8.rknn`: unpruned INT8 comparison model.
- `stock_yolov8n_448_gctx_pruned_headraw.onnx`: pruned ONNX export.
- `stock_yolov8n_448_gctx_headraw.onnx`: unpruned ONNX export.

Checksums are listed in `models/SHA256SUMS.txt`.

## Results

`paper_visem/data/results.json` contains the principal numerical results. Additional JSON files contain the tracker, detector, official-protocol and scale-adaptation comparisons used in the paper. Training curves are under `paper_visem/data/train_runs/`, and board latency measurements are in `paper_visem/data/deployment_results.csv`.

## Reproducibility scope

- The aggregated data are sufficient to regenerate Figs. 7, 9, 12 and 13 without the raw videos.
- Frame-level qualitative figures require the public videos and generated detection/tracking dumps.
- The released ONNX and RKNN files exactly match the artifacts described in the manuscript and are checksummed.
- RKNN execution requires Rockchip's runtime and cannot be reproduced on a generic desktop CPU alone.

This public code release deliberately excludes the manuscript source and
submission letter. They remain separate from the code archive until the
journal's publication and sharing policy permits release.
